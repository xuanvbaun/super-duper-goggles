# 工艺清单生成程序

## 2026-09-16：识别和复核修复

本目录是当前使用版；仓库中的 `craft-tool/` 旧版保持原样。

- 材质列的槽钢、角钢采用通用名称，例如 `槽钢80x43x5x8/Q235-A`、`角钢63x40x5/Q235-A`；产品名称、其他型材名称和分类规则保持原样。
- 按可靠表格线定位单元格，跨列文字框按原格重新识别；短表回退定位包含文本末端，避免长度数字被截断。
- 识别副本抑制红章，PDF原件及复核原图不改。异常材质、名称和规格进入复核并附原格图片。
- 型号与尺寸保留分隔；材质列从截面字段提取，避免长度或杂字符混入；带加工图号的型材保留截面，真正含子件的装配项沿用原规则。
- 名称括号不完整时补读；只有文字一致且同表存在相同完整括号说明时才补闭括号，不能凭空补名称或数字。
- 规格比较采用一致的清洗方法，保留长宽厚顺序及小数点；不把数字排序后当成相同规格。已有数字冲突继续保留原值并标记，不能把 `116.1` 无条件改成 `1161`。
- 输出中的本行重量乘积公式如果错引其他行，修复为本行 `=G*J`；原模板文件、数字格式、行高及其他填写规则保持不变。
- OCR缓存版本已更新；下次生成会使用新识别结果，旧缓存不自动删除。

验证：66项单元测试通过；使用本地总图、红章遮挡页和短表进行了真实PDF回归，检查材料行数、遮挡重量/材质及长度截断。图纸和缓存不随程序上传。

属性分类、排序、序号、标准件代号、组焊件标注等未作变更。


把"图纸材料表"PDF（扫描/图片型，无文字层）自动转换为中文工艺清单 Excel。
程序内不依赖固定路径，模板已内置，只需已装好依赖库的 Python 环境。

## 使用步骤

### 1. 准备清单文件夹
把清单文件夹放到电脑任意位置，例如：
```
D:\项目  时效炉炉体钢结构总图（图纸材料表）.pdf   ← 主清单（文件名含"总图"）
  分    时效炉侧墙拉杆1（图纸材料表）.pdf
    ...
```
若这批图纸**没有总图**（没有主清单 PDF）：把各张材料表 PDF 全部放进 `分\` 即可，顶层可以留"发图登记表/图纸清单"这类登记文件（程序会自动忽略，不会当成材料表）。程序会按引用关系挑出互不隶属的根清单，合并成一份总清单。

### 2. 运行
双击 **`运行.bat`**，输入清单文件夹的完整路径（直接把文件夹拖进窗口即可），回车。
也可以直接把清单文件夹拖到 `运行.bat` 图标上，松手即运行。
程序自动判断 PDF 类型：
- **图片型**（国内图纸/阿瑞斯）：主清单 PDF 放文件夹内（文件名带"总图"），子件 PDF 放 `分\` 子文件夹 → OCR 识别 → 表格重建 → 层级展开 → 生成 Excel
- **文字型**（瑞士/Rowa 格式）：PDF 直接放同一文件夹即可（不要建 `分` 文件夹）→ 文本提取 → 翻译排版 → 生成 Excel

输出文件保存在清单文件夹内：`工艺清单_{设备名称}（{材料表号}）.xlsx`。若同一文件夹存在多个互不隶属的根材料表，程序会按文件名顺序把所有根表及各自递归子层级合并到一个 `工艺清单_{文件夹名}（总清单）.xlsx`，不会只取第一份，也不会分别生成零散子清单。
图片型还会自动生成 **`复核报告.txt`**（对数量/重量/规格列做高倍率 OCR 复核，列出有疑问的格子，供人工抽查确认）。文件夹名的交付日期后缀会从输出名和标题里去掉（`300炉顶导风板（2026.9.14）` → `工艺清单_300炉顶导风板（总清单）.xlsx`）。

## 已实现规则

- 层级展开：总清单 + 子件全展开，层级序号（1、2.1、2.1.1…），所属代号/所属部件关联
- 多根合并：按材料表号、子图号和引用关系识别根表；多个独立根表或无层级 PDF 合并为一个总清单，同时保留各自内部层级。根的顺序按图号自然排序（`GDL161-300-09` 在 `-10` 之前），输出稳定不随缓存顺序变化
- 无顶层总清单：顶层 PDF 解析不出材料表（只有"发图登记表/图纸清单"这类登记文件）时，自动改从 `分\` 内的独立材料表按引用关系选根，合并为一份总清单；登记表本身不会被当清单输出空行
- 输出命名：项目文件夹名尾部的交付日期（`（2026.9.14）`）自动去掉，再拼 `（总清单）`
- 数量乘算：单台数量 = 本层数量 × 上层累计；计划数量列留空
- 材质列：
  - 板材：`钢板t{板厚}/{材质}`，只从厚度标注/板材尺寸表达式提取，不能取孔径或长度充当板厚
  - 管材、圆棒：`圆管或圆棒{规格去掉L长度}/{材质}`
  - 型材：`型材名称{规格去掉L长度}/{材质}`，不把重名序号粘到尺寸上
  - 标准件：`规格/标准号/强度等级(表面处理)`；PDF没有标准号时不猜填。标准件规格也常写成 `Ø6x10`（直径×长度），不会被误判成管材
  - Ares（买方供货）同样按以上分类填写；备注始终保留完整规格及加工说明
  - 材质牌号按PDF保留，不统一增加或删除前导零；非标准件缺材质时不猜填，完整尺寸仍留在备注
  - 2026-09-14 本地恢复：参照仓库bf3fb61分类规则，保留后来确认的供货件照填要求；撤销两条错误双零材质修正
- 代号 = 材料表号+件号（去字母）；行内有子图号则用子图号
- 同一父件下重名子件加序号区分（标准件不加序号）
- 备注 = 规格/设备PI号列
- 无填充颜色；K 列（单台总重）统一使用公式 `=单台数量×单件重量`
- PDF 重量/供货被 OCR 合并为同一格时会自动拆回；页脚总重与明细合计冲突时只在复核报告标记，不擅自改动源数
- `rules/corrections.json` 支持 `seq_raw_eq` 条件（按件号原文匹配），用于件号误读的定点修正

## 跨项目图号

若某行引用了其他项目/图纸的子图号，程序会自动在**同级文件夹**（上级目录下其他项目的 `分` 目录）里查找对应的子件 PDF 并展开明细。
（例如 A300 清单引用 GDL130-Q300-20 时，会在旁边的 Q300 项目 `分` 目录找到它。）

## 注意事项

- 源 PDF 为图片型，OCR 识别可能有少量字符误差，建议抽查核对
- 生成前请关闭已打开的输出 Excel（WPS/Excel 打开时会锁定文件，导致保存失败）
- 重复运行同一文件夹会使用缓存（更快）；若源 PDF 有更新，删除 `data\` 下对应缓存即可重新识别
- 不要用 WPS 保存 PDF/Excel 源文件（会被加密损坏，程序读不了）
- 程序已内置多种 OCR 误读修正与损坏文件容错；复核报告仍建议人工过一眼
- OCR 把单元格内换行读成空格时，中文之间的空格会自动去掉（`外螺 纹` → `外螺纹`）

## 2026-09-15 修复：恢复"同父件重名子件加序号"规则

- 规则原文（2026-08-13 用户第 7 条）：同一父件下的重名非标准件，名称后加序号区分（标准件不加）。
- 该规则在 2026-09-05 那轮重写里被误删（当时以"件号已能区分"为由去掉），导致 257 批次输出里
  `冷弯方形空心钢` 出现 4 次、`耐热钢板` 出现 3 次都没有序号。现已恢复为 `冷弯方形空心钢1…4`。
- 实现恢复为 `number_duplicate_names(flat)`：按父件分组计数，重名的非标准件加 1、2、3…；
  原始名称另存 `name_base`，型材材质列取 `name_base`，避免序号粘到尺寸上（`角钢1` + `50x50x5`
  → `角钢150x50x5`）。多个父件共享同一子表记录时用 `id(row)` 只编一次号，保证同名件在
  不同根清单里编号一致。
- 注意：名称本身以数字结尾的不要被误当序号——本批 `尾翼型线折弯件1/2/3`、`炉顶和侧墙拉杆1`、
  `炉顶拉杆2`、`侧墙折弯板916` 都是 PDF 原名，程序不会二次加号（它们在各父件下不重名）。
- 新增 `tests/test_dup_names.py`（6 项，覆盖加序号、标准件排除、逐父件独立计数、共享子表只编一次、
  材质列不被序号污染）；全套 45 项测试通过，257 批次重跑输出 176 行不变。
