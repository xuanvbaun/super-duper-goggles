# 工艺清单生成程序 —— 修改记录和已知问题

> 本文档记录程序历次修改项与当前已知问题，随代码同步更新。
> 最近更新：2026-09-15（恢复规则7：同父件重名子件加序号）

## 项目概述

把"图纸材料表"PDF 自动转换成中文"工艺清单"Excel 的程序，适用于阿瑞斯（ARES）熔炉设备图纸。
支持两种 PDF：
- **图片型**（国内图纸/阿瑞斯，无文字层）：OCR 流水线（pypdfium2 渲染 + RapidOCR 识别）
- **文字型**（瑞士 Rowa 等）：pdfplumber 文本提取 + 翻译排版（swiss_build.py）

统一输出到标准模板 `工艺清单标准模版-2026.6.30(1).xlsx`，文件名 `工艺清单_{设备名称}（{图号}）.xlsx`，
保存在源文件夹；图片型自动生成 `复核报告.txt`（数量/重量/规格列高倍率复核）。

## 程序流程

1. 扫描源文件夹：主清单 PDF（文件名带"总图"优先）+ `分\` 子件 PDF + 同级项目跨项目回退
2. 格式分流：文字型走文本提取，图片型走 OCR
3. OCR 缓存到 `data\<文件夹哈希>\`，重复运行跳过 OCR
4. 表格重建：找"名称"表头 → 按"数量"列位置自动识别两套模板布局 → 列切分
5. 重量列二次读取（scale6 条带按行 y 对齐补缺失重量）
6. 高倍率复核（数量/重量/规格列）→ 复核报告.txt
7. 行处理：OCR 修正 + 已确认数值修正 + 件号分配
8. 层级展开（按规格列子图号引用）→ 重名非标件加序号 → 生成 Excel

- `is_std_part` 不再只依赖分类号列（常被 OCR 读坏，如 "116 2 4"、"16 满一24"、空白）：

- 材质格清理合同号渗出 "26X"
- 规格列误读系列：`=`/`==`/`b=`/`<=`→`L=`、`K=数字`→`L=`（保留销轴 `K=120°`）、
  `L=173Q`→`L=1730`、`L=8.50`→`L=850`、`L=1.070`→`L=1070`、数字间冒号→小数点、`Q`+数字→`Ø`、
  逗号后接数字→空格、90°弯头前孤立数字清除

- do_ocr 损坏 PDF 容错：主清单读不了→清晰中文报错退出；子件读不了→跳过不展开
- 高倍率复核、重量二次读取同样跳过损坏 PDF
- WPS 占用输出文件时自动另存为"（新）.xlsx"

**运行脚本**

### 2026-08-19（结构性修复：①跨项目覆盖 / ②缓存污染 / ④循环引用 / ⑥修正外置）

**① 跨项目查找不再覆盖本项目子件**

  - PDF 更新过（大小/时间变化）自动换新键重新 OCR，不再用旧缓存
- `build_tables(cache_dir, only_names=...)` 只读取本次实际扫描到的 PDF 对应缓存，已删除子件的旧缓存不再进入 sub_map/复核报告。

**⑥ 已确认修正外置到 `rules/corrections.json`**

- 高倍率复核维持"发现差异→报告→人工确认"模式，不自动采用高倍率结果（高倍率 OCR 自身也有误读）。

### 2026-08-24（启动链修复：多 Python 版本时自动挑装有依赖库的解释器）

**现象**：机器上同时装了 Python 3.12 和 3.11，依赖库只装在 3.11 里。运行.bat 原来只验证 `import sys` 就选 `py -3`（=3.12），导致自检时 5 个依赖库全报 ×、模板误报"被 WPS 加密损坏"（实为 3.12 没有 openpyxl，模板检查 `import openpyxl` 失败走错分支）。

**修复**
- 新增 `find_python.py`：通过 `py -0p` 枚举机器上所有 Python 版本（从新到旧），逐个测试能否导入全部 5 个依赖库，输出第一个齐全的解释器完整路径；`py` 启动器不可用时兜底测试当前解释器。
- 运行.bat 第 1 步改为调用 `find_python.py` 得到解释器路径（`for /f` 捕获输出，找不到给出中文安装指引），后续 precheck / run.py 都用该解释器执行。
- precheck.py 模板检查区分 `ImportError`（openpyxl 未装，提示看依赖库）与真正的文件损坏（WPS 加密），不再误报。

**注意**：若以后把依赖库装到新版 Python 里，程序会自动改用新版（扫描从新到旧）；无需改配置。

### 2026-09-15（恢复用户规则第7条：同父件重名子件加序号）

## 已知问题

1. **WPS 加密损坏**：任何被 WPS 保存过的 PDF/xlsx 都会变成不可读文件（文件头 `\x88\x7d\x1c`，非 `%PDF-`/`PK\x03\x04`）。
   程序已做读取容错，但源文件需从原始来源重新拷贝；**不要用 WPS 打开保存 PDF/Excel 源文件**。
2. **OCR 不可能 100% 正确**：剩余识别噪声包括 1↔L、6↔9、`黑)`（材质"表面发黑"渗出到重量列）、×/x、L= 顺序等；
   复核报告列出所有差异，绝大多数可忽略，但需人工过一眼（重点看数量/规格）。
3. **复核盲区**：
   - 只查数量/重量/规格三列，材质/名称/供货列不查（曾靠镜像件对比才发现材质误读）
   - 只查"低倍率识别到了"的格子，完全漏检的格子复核看不见（靠重量二次读取部分弥补）
4. **子图缺失**：主清单引用的子图号在 `分` 文件夹和同级项目里都找不到时，该行不展开（按设计）。
5. **主清单 Excel 压缩格式**：WPS 转 Excel 时主清单第 1 页可能变成"序号/数量/单位/名称挤在一个格"的压缩格式，
   规格/标准号/材料/重量全丢——用 Excel 单独生成会残缺，需用原始 PDF 或重新导出保留十列。
6. **跨项目扫描冗余**：同级项目文件夹会被全量扫描 OCR（即使未被引用），耗时且复核报告含无关文件。
7. **模板损坏即程序无法启动**：程序启动时读模板失败会报"文件不是 zip"，需恢复有效模板副本。
8. **openpyxl 保存中途崩溃会留下损坏输出文件**：生成失败后需检查输出文件头，必要时删除重跑。
9. **顶层发图登记表**：清单文件夹里可以放"发图登记表/图纸清单"，它会干扰主清单选择所以程序自动忽略
   （2026-09-14 起）；早期版本会把它当主清单，输出只有 1 行空数据。
10. **无顶层总清单模式依赖引用关系**：根清单靠"没有被任何子图引用"识别。图纸间存在循环引用/自引用时
   会退回"合并全部材料表"并在复核报告标"根清单识别回退（需人工确认）"，需人工核对根清单划分。

## 使用注意事项

- 运行前关闭 WPS/Excel 里打开的旧工艺清单（会锁文件导致保存失败，程序会自动另存"（新）"）
- 同一文件夹重复运行走 OCR 缓存（快）；源 PDF 更新后删除 `data\` 下对应缓存再跑
- 图片型 PDF 必须主清单在根目录、子件在 `分\` 文件夹；文字型 PDF 全放同一文件夹不要建 `分`
- 跨项目引用：相关项目文件夹放在同一父目录下
- 没有总图的批次：材料表 PDF 全放 `分\` 即可，顶层放"发图登记表/图纸清单"会被忽略
