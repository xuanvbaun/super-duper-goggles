# 本地工作流 · Windows 便携版

这是在本机运行、通过浏览器操作的程序，不是云网站。将完整程序文件夹复制到另一台电脑后使用，不依赖原电脑的 E 盘、用户名或开发环境。

## 使用条件

- Windows 10/11 x64；目前没有在另一台实体电脑或 macOS/Linux 上验证。
- 解压到自己有写入权限的本地目录，例如 `E:\AI-Workflow-Portable`。不要直接在压缩包中运行，也不要放在同步网盘目录。
- 自带 Node 24.15.0、Python 3.12.14、n8n 2.39.5 和依赖，不需要安装 Node、Python、Docker 或申请 n8n 云账号。
- 浏览器使用当前电脑已有的 Edge 或 Chrome。首次初始化和启动可能需要几分钟。
- 一台电脑只运行一份；本地端口 5678、5679、8765 需可用。服务只监听本机。

## 启动和停止

1. 双击 `start.cmd`，等待显示 `Ready` 后会自动打开数字统计页面。
2. 输入 `10, 20, 30`，检查总和 60、平均值 20，填写验收说明，再选择通过或拒绝。
3. 再次打开表单可双击 `open.cmd`。任务历史访问 `http://127.0.0.1:8765`。
4. 流程管理访问 `http://127.0.0.1:5678`，首次进入时由你创建本地管理员账号。
5. 任务结束后双击 `stop.cmd`。它会终止本程序的进程；请不要在任务执行中使用。数据不会被删除。

若提示端口占用，先停止旧版本或已经启动的副本。启动失败时查看 `logs` 下日志；不要关闭杀毒、防火墙或添加扫描排除项。

## 验收时的两种结果

人工验收页有两个选项。「验收通过」只有在任务确实通过自动检查时才会生效；如果自动检查没通过（例如输入的不是数字），页面首行会提示不能选“验收通过”，此时请选「拒绝并停止」。若仍然选了「验收通过」，程序不会崩溃，而是显示「验收未生效」并说明原因，同时提示你到 `http://127.0.0.1:8765` 的任务记录里选“拒绝并停止”关闭该任务。

## 更新流程文件

`start.ps1` 只在第一次运行时导入示例流程。如果 `workflows` 里的流程文件更新了，需要双击 `sync-workflows.cmd` 重新导入并发布，否则数据库里仍是旧流程。该脚本会提示确认，执行前请先 `stop.cmd`；**你在 n8n 界面里对这两条示例流程做过的改动（包括选的凭据）会被覆盖**。

在 n8n 流程管理页里，执行记录会一直显示为“等待中”，重启 n8n 时日志还会提示有未完成的执行。这是 n8n 对“以表单节点结尾的流程”的固有实现方式，不是崩溃；表单页、任务状态和结果都是正确的。执行记录会按 14 天自动清理。

## 换电脑与数据

分发压缩包不包含本次测试数据、账号、密码或 API Key。新电脑第一次启动会创建自己的数据库、加密配置和示例流程。

迁移自己的历史记录时：先停止程序，再复制整个文件夹（包括 `data`），在目标电脑启动。不要单独移动运行中的数据库。`data` 中可能包含输入内容和加密凭据，应只交给你信任的人；保留完整备份，尤其不要丢失 n8n 的加密配置。

默认数字统计不需要 AI 密钥。n8n 仍可能尝试访问自身许可或功能目录服务；本机表单和计算不调用 AI。

Python 对 AI 输出仅检查 JSON 是否可解析，不验证摘要事实是否准确；仍需要人工验收。

该版本验证数字统计、JSON 检查与人工验收链路，并非原始规格中的完整 AI 自动总控。Windows x64 是当前打包目标，不能承诺适用于所有操作系统、硬件和企业管控环境。
